## What Didn't Work
- Initial typo of "mpx" instead of "npx" when executing `mcporter` commands.
- Incorrect initial usage of `mcporter generate-cli` flags (specifying a directory for `--output` instead of a file path for the bundled output when `--bundle` was used), leading to a command failure.
- Repeated truncation of large text blocks when using `echo` directly in the prompt, necessitating a change in strategy to write content to a file for complete delivery.

## Pitfalls & Lessons Learned
- **Distinguishing Client vs. Server:** It was important to clearly establish `mcporter`'s role as a client to MCP servers, not a server itself, to avoid confusion in configuration.
- **`generate-cli` Output Paths:** The `--bundle` flag for `mcporter generate-cli` requires an explicit output *file path* for the bundled executable, not just a directory, and behavior regarding `--output` (for source) vs. `--bundle` (for executable) needs careful distinction.
- **Agent Output Limitations:** Direct `echo` for very long explanations can lead to truncation; writing to files and instructing the user to read them is a more robust strategy for comprehensive information transfer in such cases.
- **User vs. Developer Integration:** It was crucial to differentiate between developer-level integration (modifying Gemini CLI's source code) and end-user integration (running external commands via Gemini CLI's shell execution capability).

## Future Work & Ideas
